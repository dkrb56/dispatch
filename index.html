Dispatch runs Claude Code as a team. One session, triage, takes your tasks and starts workers in the background. You give the tasks and answer the questions. The workers do the work.

Before you start

You need Claude Code and a project folder.

  • Install Claude Code and sign in. The command claude must start in a terminal.
  • Use a git repository for the project if you can. A folder without git also works.
Details
  • In a git repository, Dispatch uses the top folder of the repository as the project.

Set up a project

Do these steps one time for each project.

  1. Click + in the projects group of the top bar. Select the folder of your project. A new project shows the Setup pipeline window.
  2. Read the steps. Each step shows "To do" or "Done". Nothing changes yet.
  3. Click Apply. Dispatch does the steps that are not done. It makes no commit.
  4. Click Commit to git. Dispatch commits the setup files.
  5. Click Close. The workspace opens: triage at the left, the workers at the right.
  6. Type your first task in the triage chat. Triage tells you when the plan is ready.
Details
  • In the modes Use hosts and This PC and hosts, the folder chooser of Dispatch opens. With several computers, it asks for the computer too (see Where the work runs).
  • A project that is set up skips the window and opens its workspace: go to step 6.
  • Click a step to see its file and the text that it adds.
  • Under the steps, the window lists the rules of the project that conflict with the pipeline, each with its file as a link. A click opens the file in the viewer, also for a rule outside the project. Open in editor there lets you change the rule yourself.
  • Apply makes no commit, so you can look at the changes in git first. When all steps are done, Commit to git becomes available.
  • Commit to git commits on the current branch: CLAUDE.md, the three files in .claude, and the script, the two options files, the measure commands and the gate command in .dispatch. Your other changes stay out of the commit. Dispatch makes no push.
  • The window shows the commit, or the reason for no commit: no git repository, nothing to commit, or the error of git.
  • A work run starts only when the project has no uncommitted changes outside .dispatch. Without the setup commit, the first approval is refused and names the setup files. Dispatch commits the task files in .dispatch itself.
  • The workspace is a new tab with two terminals. Claude Code starts in both.
  • A close with a step still To do adds nothing. Click + again to start over.

What Setup pipeline changes

Apply writes these files into the project.

StepWhereWhat it does
Task files.dispatchHolds the briefs, plans, reports and the state of each task.
Allow rules.claude/settings.local.jsonTriage runs the worker script without a permission prompt.
Worktree isolation off.claude/settings.jsonWorkers work in the project folder, so you see their changes.
Section in CLAUDE.mdCLAUDE.mdAdds the rules for triage and the workers.
Working rulesCLAUDE.mdAdds rules for the work, for example plain words.
Worker script.dispatch/worker.ps1Starts, resumes and stops a worker.
Measure before the plan.dispatch/measure-commands.txtOptional: commands that the plan run may run.
Task branches.dispatch/merge-gate.txtOptional: each task gets its own git branch.
Triage role.claude/triage.mdTells triage to plan and check, not to implement.
Details
  • Task files. Each worker writes its report and the state of its task into .dispatch. Triage writes its briefs to briefs, and each worker writes its plan to plans.
  • The options of the two runs are in plan-flags.txt and work-flags.txt. The lists above Workers change them.
  • Git tracks the folder, so a clone has the history of the tasks. Dispatch commits these files itself (the commit message starts with "Dispatch:"), except while a work run runs without a report. Approve does not count them as changes.
  • A project of an older version has the folder <project>-reports next to it. Apply moves its files into .dispatch and overwrites nothing. The step shows the number of files first.
  • Allow rules. Triage can run the worker script and check workers without a prompt. A deny rule keeps the approve verb of the script for the Approve button. Each session can read and write the task files in .dispatch without a prompt.
  • Apply removes the rules of an older version that name <project>-reports. Triage can also read the job folders of the workers (%USERPROFILE%\.claude\jobs), where a worker keeps the screenshots of its visual test.
  • Worktree isolation off. A worker works in the project folder, not in a separate copy.
  • Section in CLAUDE.md. The section "Background workers": a task is two runs of one worker, the plan run edits nothing, your yes starts the work run, and the worker ends with one local commit and never pushes. Apply replaces a section with an older text.
  • Working rules. The section "Working rules": plain words, no duration estimates, only the user's words are approval, reproduce a bug before the fix, scripts write the proof, and more. Each rule has a checkbox. Apply adds the checked rules. With no checked rule, Apply adds no section.
  • Worker script. Triage runs it to start a plan run and to send your follow-ups. Dispatch runs it when you click Approve, Reject, Stop or an answer. It refuses to start the work run when the project has uncommitted changes, when the worker still runs, or when the task was stopped.
  • Measure before the plan. Off: the step is done, and nothing changes. On: the plan run may run the commands of the box under the switch, and no other command, through the worker script. The step is done when the box has a command.
  • Each command runs with cmd.exe in the project folder, one at a time in the project. It stops after 10 minutes; a first line # limit <seconds> changes that. The output and the throw-away scripts go into .dispatch/measure/<task>/, which git ignores (Apply adds measure/ to .dispatch/.gitignore). When a command changed files of the project, the task card says so.
  • Task branches. Off: the step is done, and nothing changes. On: each task works on its own branch task/<task>. Approve makes it from the branch that the project was on when the plan run started (the base). The worker commits there and never merges or pushes.
  • When the report is written, Dispatch switches the project back to the base and commits the task files there. Then the task card shows Merge. The gate command of the box under the switch runs on the merged code first, for at most 4 hours; a first line # limit <seconds> changes that.
  • The log of the gate goes into .dispatch/merge/, which git ignores (Apply adds merge/ to .dispatch/.gitignore). The step "Allow rules" adds a deny rule, so triage cannot merge.
  • Triage role. The text tells the session in the Triage terminal that it is triage: it plans and checks, and it does no implementation. The project settings change this text.

Project settings

Switches in the Setup pipeline window for this project.

  • Short reports. Triage tells you the result and your decisions in a few lines. It gives details when you ask.
  • Fixed title. A new triage chat has the name "Triage" in the chat list.
  • Approve plans automatically. Dispatch starts the work run when a plan is ready.
  • Measure before the plan. The plan run may run your commands before it writes the plan.
  • Task branches. Each task works on its own git branch.
  • After a change, click Apply.
Details
  • Short reports and Fixed title are on for a new project. The other three are off. A project that was set up before stays off for Measure before the plan and Task branches.
  • A change of Short reports applies to a new triage chat only, because a chat keeps the role with which it started. The next start of the workspace (the folder button of the project, or the start of the app) opens a new triage chat.
  • Approve plans automatically applies at once. It waits when the project has uncommitted changes or another work run runs. A plan with a decision marked HOLD: waits for your click. The line in the triage chat says "approved automatically".
  • Measure before the plan. Write the commands into the box under the switch: the tests, a browser test, a measuring script. The plan then has a section "Measured" with each command, what it showed and what it means. A fault that the plan run did not reproduce says "not reproduced".
  • The plan run still edits no file, starts no agent and asks you nothing. Apply changes the options of the plan run and the section in CLAUDE.md with the switch.
  • Task branches. Your branch stays clean until you merge. Approve makes the branch task/<task> from the branch that the project was on at the plan run, and the worker commits there.
  • When the worker is done, Dispatch switches the project back to that branch. The task card then shows Merge into <branch>.
  • Write a gate command into the box under the switch, for example your test suite. Merge runs it on the merged code and makes the merge commit only when it passes. Night mode does not merge.

The workspace

The triage chat at the left, the workers at the right.

  • Triage (left). Type your tasks here. Triage plans each task with a worker and tells you when the plan is ready.
  • Approve the plan in the task card. The worker does the work, and triage reports the result.
  • A message waits as a planned message until triage is free. Dispatch sends them one at a time, in your order.
  • Chat and Terminal above Triage select its view. Chat shows formatted messages. Terminal shows Claude Code itself.
  • Workers (right). This is the agent view of Claude Code. Select a worker to see its work or answer a prompt.
  • Environment in the side panel shows the shell, folder, branch and session of a terminal. Its Remote Control switch turns Remote Control on or off.
  • The yellow button in the top bar shows when a worker waits for you. Click it to open that worker.
  • Old sessions. The button N old lists finished worker sessions that Claude Code still keeps open. End closes one.
  • The folder button of a project opens its workspace again and continues its last triage chat.
Details
  • For each task, triage writes a brief and starts the plan run of a worker. Dispatch writes one line into the triage chat when a worker is done, blocked or failed, and when you approved, rejected, stopped or answered in the Tasks section.
  • A planned message is a file in .dispatch/backlog/ of the project. A message that starts with / (a command of Claude Code) goes at once. The Overview and the Tasks section tell more.
  • You can click Approve also while another work run edits the project or the project has uncommitted changes. The card then says "Approved · waits for the project", and Dispatch starts the work run when the project is free. Cancel approval takes it back.
  • A question of triage shows its options as buttons. Click one, or press Ctrl+Enter for the first.
  • In the Chat view, Enter sends the message and Ctrl+V adds an image from the clipboard. A permission prompt of triage ("Allow this read …?", "Do you want to proceed?") shows as buttons too, marked Permission.
  • Other… opens the terminal for an answer in your words. Cancel at the right end leaves a question without an answer, like Esc in Claude Code; triage then waits for your message. A permission prompt has no Cancel: use its No.
  • Use the Terminal view for a menu or a slash command.
  • Commands in the chat. A code block has a copy button at its top right. A one-line command also has ▶: it runs the command in a Commands terminal of the project, in the project folder, below the triage chat.
  • The Commands terminal stays for the next command. While a program still runs in it, the next command gets a second one. A command with a part in <…> goes in without Enter: fill in that part, then press Enter. The × of its bar closes it.
  • Remote Control. A click on off types /remote-control into that session, on this PC or on its host. The row says "turning on …" until Claude Code confirms; then it shows the real state again.
  • A click on on types /remote-control too and chooses Disconnect this session in the menu of Claude Code. The row says "turning off …" meanwhile. When the menu does not show as expected, Dispatch closes it with Esc and changes nothing. The switch is grey while the session works or waits for an answer.
  • Model and effort. The two lists above Triage apply at the next start of triage. Above Workers, plan sets the plan run and work the work run; they apply to the next run that triage starts.
  • Agents. A worker can start agents for parts of its task in its work run. The fifth list above Workers sets the maximum number of agents that one worker runs at the same time. A plan run starts no agent.
  • The number next to that list is the sum of the agents that the workers of the project started; it shows only when a worker started an agent.
  • N old shows when a session belongs to a finished task (done, failed or stopped), or a newer run of its task took over (Approve and each answer start a new run). It stands among the buttons of its project and counts that project only. In the Map and the Overview the top bar has N old sessions for all projects.
  • Each row of the window shows the session name, its state, why it counts as old, what Claude Code still keeps, and when it started and ended. End runs claude stop on the computer that runs the session; its conversation is kept. The task, its report and its state file do not change, and the triage chat gets no line.
  • A task that works or waits for you is never in that list, and neither is a session that you started by hand. The list covers the projects that Dispatch shows.
  • A later Setup pipeline changes the settings and does the steps that are not done.
  • A new triage chat at a limit. The third list above Triage, new chat at …, sets how much context the triage chat may have: 100k to 400k tokens, 200k at the start. no new chat turns it off. It applies per project.
  • At the limit Dispatch waits for a quiet moment: triage does not work and asks nothing, the Chat view shows an empty message box, no line of Dispatch waits, night mode is off, and for 2 minutes there was no turn of triage and no key or click in Dispatch.
  • Then Dispatch closes the chat with /exit and starts a new triage chat in the same pane, with the model and effort above Triage. In the Terminal view the new chat does not start, because Dispatch cannot see what you type there.
  • The hand-off. The first message of the new chat comes from Dispatch: the open tasks and their state, how many are finished, and where the task files are. It holds nothing of the old chat. The lines of Dispatch that came during the switch follow it.
  • The old chat stays in the chat list as "earlier triage"; nothing is deleted. If Claude Code does not end within 30 seconds after /exit, the old chat stays, and Dispatch tries again after the next turn. If Dispatch closes during the switch, the next start of triage starts the new chat with the hand-off.
  • At the start of the app, a project with a workspace opens it by itself: triage continues its chat and the agent view starts.

Focus mode

One column for each project, side by side, with its chat and tasks.

  • Focus at the left of the bar opens it. Details goes back to the terminal tabs and the chat list.
  • Each project has a pill in the bar: green while a worker works, orange while something waits for you.
  • The head of each column has the buttons of its project: Rules, Setup, N old and the folder button.
  • Workers in the head of a column opens the agent view of that project. A second click closes it.
  • With two or more projects, a blue frame marks the project you work in.
Details
  • Overview shows less: for each project only the tasks in work and a message box.
  • The Triage card at the top of the left panel shows how full the triage chat is: the tokens in use, the size of the window and the share, with a thin bar. It updates within about 10 seconds after a turn. At the limit it says "new chat when quiet", and "starting a new chat…" during the switch. Its tooltip says what the new chat waits for.
  • The first time, focus mode takes the projects whose workspace is open. The projects group with its pills and + stands in the bar in Details, Focus and Map; the Overview hides it.
  • + adds a project folder. The × of a column removes the project from focus mode only.
  • A project that is not set up shows the Setup pipeline window first after +. Then its workspace starts and the project joins focus mode. A removed project keeps its workspace in Details.
  • Drag the right edge of a column to give a project more room. Drag the edge between the left panel and the chat to widen the panel. Each project remembers its sizes; a double-click on an edge goes back to the usual size.
  • The pills show the projects of focus mode, or the projects with an open workspace when focus mode has none. A click goes in Focus to the column, in the Map to the graph, and in Details to the workspace tab (a project without a workspace gets one).
  • In Details the current project is an open group with a blue frame: its dot, its name, its state and its buttons. The current project is the one of the focused terminal, else the one you clicked or typed in last.
  • The other projects are closed pills: a green number while workers work, "waits" in orange while something waits for you. A click on a closed pill opens its group; one group is open at a time. In Focus the bar shows closed pills only.
  • N old shows only when the project has old sessions. After the buttons of the project come Map, Workers and ×.
  • The agent view is closed at the start. A click on a worker row opens it too, and the × of its bar closes it. The workers go on working while it is closed.
  • With two or more projects each project has a thin grey frame, and a blue frame marks the project you work in: the one you clicked or typed in last. Dispatch remembers focus mode and its projects at the next start.

The Map

Each project as a graph: what runs and what waits for you.

  • Map at the left of the bar opens it. Each task is one row with its runs and agents.
  • Green works, orange waits for you. Click something orange to decide, approve or answer.
  • Click a run to open the worker view: what the worker and its agents do now.
Details
  • The graph shows you, triage, the tasks and the agents of the work run. A dashed box starts when you approve. The wires show what passes: tasks to triage, briefs to the plan runs, the approved plan to the work run.
  • A click on something orange shows its card at the right: the plan with Decide, Approve and Reject, or the question of a worker.
  • The worker view shows the worker, its agents, the last three tool calls and the last message of each, the tokens and the context, the tool calls by tool, the changed files, and a timeline of all tool calls. Under the run box it says what the task is about and what it did or does.
  • Dispatch reads the session files twice a second. Claude Code writes a line when a tool call starts and ends, so a message shows when it is complete. Pause stops the updates while you read. Map goes back.
  • The Map shows every task that waits or runs, and the 5 newest finished ones; the others fold into "N more tasks". With many rows, You and Triage stand at the top. In focus mode, Map in the head of a column opens the Map at that project.

Overview

One small card for each project.

  • Overview at the left of the bar opens it.
  • Drag a card by its grip ⠿ to any place. It snaps to a 50 px grid; the dots show the grid.
  • Each card has In work, Done and Planned. The tasks have the same buttons as in the Tasks section.
  • The box at the bottom sends a message to the triage chat of the project. The chat itself does not show.
Details
  • The Overview shows each project with an open workspace. You can also drag a card anywhere on its head but the name. The top left corner of a card lands on a dot.
  • Dispatch keeps the places on this computer, so a restart shows them again. The card of a new project takes the first free place. A card that you drop on another lies on top of it; the card you moved last is always on top.
  • In work lists a worker that runs, a plan that waits for Approve, a question or a permission of a worker, a worker at a prompt, a plan that you approved until its work run starts, and the message that triage reads now. Without one it says "Nothing in work".
  • Done shows the 5 newest tasks that ended (done, failed or stopped), newest first. Planned shows your messages that wait for triage, in their order. Each task shows the same two lines as in the Tasks section.
  • Planned messages. Each message that you send from the box is a planned card first, also when triage is free; you can type many in a row. Drag a card by its grip, or click ▲ or ▼, to change the order; × removes it. When triage is idle and asks nothing, Dispatch sends the first message, word for word. A command that triage runs in the background after its answer does not hold the message.
  • Until then the message waits while triage works, also during a long command of its turn. The line above the box says how many messages wait. Its card then stands under In work and says "Sent to triage". When triage starts the plan run, the task card takes its place. A message that gives no task goes after the answer of triage.
  • Each planned message is a Markdown file in .dispatch/backlog/ of the project, so it stays after a restart. You can edit or delete a file in an editor; Dispatch follows within a few seconds. Dispatch commits each change of these files at once, with only these files (the commit message starts with "Backlog:"). Focus and the Tasks section show the same cards under Planned.
  • The message box has the keys of the chat: Enter sends, Shift+Enter makes a new line, Ctrl+V adds an image. A text that you began in Focus stands in it too.
  • The line above the box says when triage works or waits. While triage asks a question, the question shows above the box with its buttons; Other… opens the project with its terminal.
  • Record of a question from the screen. Claude Code writes a question into the chat only after your answer, so Dispatch reads the open question from the terminal. Each read goes into a file in the folder menu-reads in the data folder of Dispatch, named menu-<date>-<time>-<pane>.json.
  • The file holds the screen text of each read, which lines the terminal wrapped, the question and the options that Dispatch made of it, and the times. Dispatch keeps the newest 50 files. When a question shows a wrong text or wrong buttons, give the newest file to triage with your report.
  • A click on the name of a project opens it in Focus, or in its tab when focus mode does not have it. A click on a run opens the agent view of the project the same way. Dispatch remembers the Overview at the next start.

Night mode

The work goes on while you are away.

  • Turn on the Nightmode switch in the bar when you go away. It is green while night mode is on.
  • Dispatch approves plans and answers questions with their recommended option. A HOLD decision and a permission still wait for you.
  • The computer that does the work stays awake while the switch is on.
  • In the morning, Morning at the top of a column shows the defaults that night mode took.
Details
  • The switch is the one state of night mode. The program that does the work keeps it: Dispatch in the mode This PC does the work, each host in the mode Use hosts. In the mode This PC and hosts, Dispatch keeps the switch of this PC and each host keeps its own; the one switch in the bar shows them together. So a restart brings it back as you left it, and every window of a host shows the same switch.
  • With several hosts each host has its own switch. The switch in the bar is on when every host is on, and off when every host is off. When the hosts differ, the knob stands in the middle; its tooltip names the hosts that are on and off. A click on that look turns night mode on for every host.
  • A host that is not reachable keeps its own switch and is left out of the look until it is back.
  • The display may turn off. When the switch goes off, or the program ends (also at a crash), the computer sleeps as before. A computer that only shows a window may sleep.
  • Keep a window open on a computer that stays awake, because the automatic actions of night mode run in a window. The window on the host's PC takes over within about 30 s when the other window sleeps. On a Mac, Dispatch runs the system tool caffeinate.
  • On and off send /nightmode start and /nightmode end and a Dispatch line to the triage chat of each project with a workspace. Triage keeps the list of the defaults and writes the morning file (your nightmode skill).
  • The triage chat follows the switch. At each start and each new triage chat, Dispatch compares the switch with the night file of the chat (.claude/state/night/night-mode.json) and sends the command again when the chat is behind. The chat never changes the switch.
  • Dispatch writes the chosen defaults into the plan, and triage hears each default. A plan with a HOLD decision and a report that needs a permission wait; triage puts them under Reminders.
  • The morning file is .claude/state/night/morning-<date>.md. Morning opens the newest one: the defaults with their options, what was built, and what waits for you.
  • A question of triage about the night defaults has View defaults in the Chat view. It opens the morning list in the viewer, and the question stays open: close the viewer, then answer or cancel. Without a morning list the button says "No morning list found".

The Chats panel

The triage chat, the tasks and your other chats.

  • Triage at the top opens the triage chat of the project.
  • Tasks shows each task with its worker rows, its plan and its report. Click a row to open it.
  • Each task shows two short lines: what it is about, and what was done or is in work.
  • Plan ready. Click Approve all to take the recommended options. Click Decisions to choose each option.
  • Reject sends the plan back with your reason.
  • Questions. A question of a worker shows its options as buttons. Click one for each question.
  • Merge. With Task branches on, a finished task shows Merge into <branch>.
  • Stop. Ends a worker that runs. A stopped task cannot go on.
  • Chats lists your Claude Code chats. Click one to continue it in a new tab.
Details
  • A triage chat that Dispatch replaced with a new one stands under Chats with the mark "earlier triage".
  • Older chats at the end of the list holds the chats that started before the Dispatch setup of the project, also when Claude Code still has them open. A project without the setup has no Older chats. Click it to show or hide them. A search shows them.
  • A worker row says Plan run (it reads the code and writes the plan) or Work run (it executes the approved plan). Approve starts the work run as a copy of the plan run.
  • A worker row shows the state, how long the worker took ("42 s", "4 min", "1 h 12 min") and, when the worker started agents, their number ("3 agents"; "3 agents, 2 active"). The start and the end stand in its tooltip. The Map shows the same durations.
  • In the agent view the two runs are named <task> [plan] and <task> [work]; a project gets these names after Setup pipeline → Apply.
  • The files of the files: line of a report show as a row of links at the top of the viewer, and a file name in code in the text of a report or a plan is a link. A name whose file is not there gets a mark. Open in editor opens the shown file in the program of this computer, only for a file of this PC.
  • The plan row shows when the plan file changed and has no state chip, so it does not look like a run; the state of the task stands in the header of the card and in the tooltip of the row. The report row shows the state from the first line of the report.
  • The two lines come from the title of its brief (else your words in the brief, else the title of the plan), and from the first Summary line of the plan, the first line of the report, or the open question. Dispatch writes nothing itself: the text is cut from the brief, the plan and the report. A long line ends in “…”; its tooltip has both lines in full.
  • A task that you approved while the project was not free shows under its state, with an eye before it, which work run it waits for or how many changed files wait for a commit.
  • A message that you send to triage is a planned card under Planned first (see the Overview). When Dispatch sends it, it shows as a temporary card with a dashed edge: your message, the time, and "Sent to triage", then "Triage reads" while triage works on it.
  • The temporary card stands where the new task will stand. When triage starts the plan run, the real task card takes its place. When triage answers without a task, the card goes a few seconds after the answer, or at the latest after 10 minutes. The card stays when you close and open Dispatch. It has no buttons and starts no worker.
  • Approve all also takes the HOLD decisions, writes the options into the plan under "User decisions", and starts the work run. A plan without decisions shows Approve. A task that waits for you is first in the list.
  • The Decisions window starts with your words from the brief, the Goal and the TL;DR of the plan. Click an option, or type your own answer under Other. Then click Approve with these decisions, or Send back to the planner to revise the plan with them.
  • Approve is grey while the project has uncommitted changes or another work run of the project runs; the reason shows below it.
  • Your answer goes to the worker word for word, with the number of the question in front. With several questions each click is a choice: the chosen option is marked, and another click changes it. When every question has a choice, the answers go to the worker together in one reply.
  • A new question also opens a window by itself; Answer in a window in the card opens it again. Click the options, then Send the answers. The window does not open by itself in night mode, at the start of Dispatch, or while another window is open.
  • A worker that stopped at a refused step says so in its report, and the task shows Continue. Change the rule first, then click it.
  • Merge. The task shows its branch, the branch it came from, and where it stands. A click merges with a merge commit after the gate command passed, and the Approve of another task waits meanwhile. A failed gate, a conflict in your code or uncommitted changes merge nothing; the card shows why.
  • A conflict only in the task files of .dispatch takes the version of your branch. Dispatch deletes the merged branch and writes one line into the triage chat. It makes no push. When the worker left uncommitted changes, the project stays on the task branch.
  • Stop asks first: Stop now ends the worker through the worker script, and Keep running lets it go on. Dispatch writes one line into the triage chat. The rest of the work needs a new task.
  • This project and All projects select the chats that the list shows. The search field finds a chat by its title or its folder.
  • Drag the right edge of the panel to change its width; the terminals keep at least 360 pixels. The width is also the usual width of the left panel in focus mode. A double-click on the edge goes back to the usual width.

Where the work runs

Do the work on this PC, or on other computers (hosts).

  • Options has three modes. This PC does the work is the default.
  • Use hosts: other computers do the work, and this window controls them.
  • This PC and hosts: this PC works, and this window controls the hosts too.

To work from a second computer, do these steps one time.

  1. On the computer that does the work, open Options. Click Start the host in Run the host on this PC. The Key box shows the key of the host.
  2. On the other computer, open Options, select Use hosts and click Add host. A new row shows.
  3. Fill in the name, the Tailscale address and the key.
  4. Close Dispatch and start it again. The window connects to the host.
  5. Click + and select a folder of the host.
Details
  • A change of the mode or the hosts applies at the next start of Dispatch.
  • This PC does the work: Dispatch runs the terminals, Claude Code and the workers here, and nothing listens on the network. Use hosts: the hosts run the program dispatch-host, and nothing runs on this computer. This PC and hosts: no host program runs on this computer.
  • Start the host: the host listens on the Tailscale address of this computer and on 127.0.0.1, never on all addresses. Dispatch adds the row 127.0.0.1 with the name "This PC", switches this window to Use hosts and starts again. On Windows, Start the host at each Windows sign-in starts it after each sign-in.
  • The row has Name, Address, Port, Key and Remove. Address: the Tailscale name (name.tailnet.ts.net) or the 100.x address. Port: empty is 7470. Key: copy it from the Key box, or from host-key.txt in the data folder of the host.
  • The window connects to every host of the list. The title says "Dispatch · host <name>" with one host and "Dispatch · hosts <name>, <name>" with more. The workspace of a host folder opens on that host.
  • Several hosts. One window shows the projects of every host. With more than one host, each project name gets " · <host name>" after it, so two projects with the same folder name stay apart. With one host the names do not change.
  • This PC and hosts. This computer counts as one more computer named "This PC", first in the list. The title says "Dispatch · This PC + host <name>", and each project name gets " · This PC" or " · <host name>". The bar at the bottom names the computer of the focused terminal.
  • A tab or a project saved in the mode This PC does the work stays on this PC. Nothing on this computer listens on the network. Start the host switches the window to Use hosts, because the host then does the work of this PC.
  • Where a new terminal runs. The first tab at a start without saved tabs runs on the first computer of the list. A split runs on the computer of the focused terminal. A chat or a worker opens on its own computer.
  • The folder chooser. In the modes Use hosts and This PC and hosts, + opens a folder chooser inside the window. It starts at the home folder of the host. Click a folder to go into it, or type a path and press Enter, then click Choose. With several hosts a list box at its top selects the host. In the mode This PC does the work the folder dialog of the system opens.
  • A host that is gone. A bar below the top bar shows one row for each host that is not reachable. Dispatch tries again after 1, 2, 4, 8 and 10 seconds. The other hosts keep working. Typing into a terminal of the gone host goes nowhere, and nothing on that computer stops. When the host is back, a terminal that still runs there continues.
  • A host that refused the window, for example with "the key is wrong", gets a row with its reason and Try again. Correct the key in Options and start Dispatch again.
  • What travels between the computers. Only the window and its hosts talk, only on the tailnet, and Tailscale encrypts the traffic. The window sends the key, the versions and its id first. Then your keystrokes, the terminal output, the chats, the task files, the shown files and pasted images travel.
  • The window keeps its tabs, saved screens, theme and other choices on its own computer. The host keeps the terminals of a closed window, the Nightmode switch and the triage chats of its projects. A file of a host opens in the viewer only.
  • Run the host on this PC in Options: Stop the host ends the host and its terminals, removes the row 127.0.0.1 and starts Dispatch again; with an empty list this window goes back to This PC does the work. New key starts the host again with a new key; every other window needs the new key.

Other buttons

The rest of the buttons.

  • The four icons split the terminal right or down, close it, and show or hide the side panels.
  • The buttons of a project. Rules, Setup, N old and the folder button act on that project.
  • Rules shows all the rules that Claude Code gets in the project. Analyse rules finds old or bad rules.
  • Update to … shows when a new version is ready. Click it to install the update.
  • Options (the gear) holds the mode, the alerts, the colour theme and the size of the text.
  • Alerts. Dispatch tells you when a task waits: a notification, a chime, and a taskbar button that blinks.
  • The bar at the bottom shows your Claude account, its weekly usage and the versions.
  • What's new next to Check for update lists what each version brought.
  • ? opens this help.
Details
  • In Details the buttons of a project stand in the group of the current project in the bar; in Focus in the head of each column. Setup opens the Setup pipeline window. N old shows only when the project has old sessions. The folder button opens the workspace; a project that is not set up shows the Setup pipeline window first.
  • In the Map and the Overview the right side of the top bar keeps Rules, Setup pipeline and N old sessions. Rules and Setup pipeline act on the project of the focused terminal there, and N old sessions shows the old sessions of all projects.
  • Copy all puts the rules into the clipboard as text. The three lists left of Analyse rules set the time limit of the check (3 to 30 minutes), the model and the effort. The Setup pipeline window uses the same values. While a check runs, the line above the findings shows the time that passed and the limit.
  • Each finding has a link with the name of its file; a click opens the file in the viewer.
  • Each rule of a Markdown file has two buttons. Off takes the rule out of the file; the list keeps it with a line through it, and On puts it back at the end of its group. Remove deletes the rule after a second click. The rules that are off are kept on this computer only.
  • A rule of the triage role comes back with the next Apply of Setup pipeline. The settings in JSON files have no buttons.
  • The update saves your tabs, downloads the installer and installs: Dispatch closes, a progress bar runs, and the new version opens with your tabs. The check reads the public releases on GitHub and needs no login.
  • On a Mac the click downloads the disk image and opens it, and Dispatch closes. Drag Dispatch to Applications. The app is not signed, so run xattr -cr /Applications/Dispatch.app in Terminal once before the next start.
  • The line below the title of this window shows the version and the result of the check. Dispatch checks once an hour; Check for update checks now, and installs a new version that it found.
  • The Options window holds where the work runs (see Where the work runs), the alerts, the colour theme of the window and the terminals (Slate, or Graphite with a blue, indigo, teal or amber accent) and the size of the text (90 to 150 percent). A change applies at once, and Dispatch keeps the choices on this computer.
  • An alert comes one time when a plan is ready, a report has a question or needs a permission, or a worker waits at a prompt. Each alert has its own switch in Options. The notification names the task and what it waits for. The button blinks until you open the window.
  • The tasks that already wait when Dispatch starts give no alert. The chime plays only after your first key or click in Dispatch, because the window may play sound only then. In night mode only a plan with a HOLD decision, a permission and a prompt alert. A test build that runs with npm run tauri dev shows the notification as from PowerShell.
  • The bar at the bottom shows "Claude account:" with the email of the account that Claude Code uses on the computer that does the work. Then come the weekly usage for all models and for Fable, the version of Claude Code and the version of Dispatch. The email stays on this computer.
  • The computer that does the work is this PC, or the computer of the focused terminal with hosts. With several hosts the host name stands in front of the account. When the versions of this window and a host differ, the bar shows both in the wait colour.
  • Dispatch reads the account and the versions at the start and then once a minute. Without a login the bar says "Not signed in to Claude Code"; without Claude Code it says "Claude Code not found".
  • The weekly usage, for example "Week: all models 41 % · Fable 7 %", is the used percent of the weekly limits of your subscription, as /usage of Claude Code shows it. After it the bar shows when the week starts again, for example "Resets Jan 1, 9:00am"; the tooltip adds the time zone and when Dispatch read it.
  • Dispatch reads the usage at the start and then every 5 minutes. Each read starts Claude Code for a moment without a window, and Claude Code asks Anthropic for the numbers. The numbers stay on this computer.
  • When the usage cannot be read, the bar says "Usage not known" and keeps the last values. An account without a weekly limit shows "No weekly limit", and "Fable: no weekly limit" when the usage screen has no line for Fable. In a narrow window the email is cut first, then the versions.
  • After an update, What's new opens once by itself with the versions since the one you had before. The text is the file CHANGELOG.md in the repository of Dispatch.

Options

Where the work runs

A change here takes effect at the next start of Dispatch.

Run the host on this PC

The host is not running.

Start runs dispatch-host from the folder of Dispatch, adds or updates the row 127.0.0.1 of this PC in the host list, switches this window to Use hosts (also from This PC and hosts) and restarts Dispatch; the terminals of this window end. Stop ends the host and its terminals, removes that row and restarts Dispatch; with an empty list this window goes back to This PC does the work. New key restarts the host with a new key; every other window needs the new key.

Alerts when a task waits for you

An alert comes one time when a task starts to wait: a plan is ready, a report has a question or needs a permission, or a worker waits at a prompt. While night mode is on, only what night mode leaves to you alerts: a plan with a HOLD decision, a permission and a prompt.
