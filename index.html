Dispatch runs Claude Code as a team. One session, triage, takes your tasks and starts workers in the background. You give the tasks and answer the questions. The workers do the work.

Before you start

  • Install Claude Code and sign in. The command claude must start in a terminal.
  • A project that is a git repository is best. Dispatch then uses the top folder of the repository. A folder without git also works.

Set up a project

Do these steps one time for each project.

  1. Click Project and select the folder of your project. In the modes Use hosts and This PC and hosts the folder chooser of Dispatch opens; with several hosts, or this PC and a host, it asks for the computer too (see Where the work runs). A project that is not set up shows the Setup pipeline window. A project that is set up opens its workspace at once: go to step 6.
  2. Read the steps. The window shows the project settings and seven steps. Each step has the mark "To do" or "Done". Nothing changes at this time. Click a step to see its file and the text that it adds.
  3. Click Apply. Dispatch does the steps that are not done. It makes no commit, so you can look at the changes in git first. When all steps are done, the button Commit to git becomes available.
  4. Click Commit to git. Dispatch commits the setup files of the project on the current branch: CLAUDE.md, the three files in .claude, and the script and the two options files in .dispatch. Your other changes stay out of the commit, and Dispatch makes no push. The window shows the commit, or the reason when there is no commit: no git repository, nothing to commit, or the error of git. The work run of a task starts only when the project has no uncommitted changes outside .dispatch. Without this commit, the first approval is refused and names the setup files. The task files in .dispatch need no commit from you: Dispatch commits them.
  5. Click Close. The workspace opens: a new tab with two terminals, Triage at the left and Workers at the right. Claude Code starts in both. A close with a step still To do adds nothing; click Project again to start over.
  6. Type your first task in the Triage terminal. Triage starts a worker that writes a plan and tells you when the plan is ready. You approve the plan in the Tasks section of the Chats panel. The same worker then does the work, and triage tells you the result.

What Setup pipeline changes

StepWhereWhat it does
Task files The folder .dispatch in the project Each worker writes its report here, and the state of each task is here. Triage writes its briefs to the folder briefs, and each worker writes its plan to the folder plans. The options of the two runs are in plan-flags.txt and work-flags.txt; the lists above Workers change them. Git tracks the folder, so a clone has the history of the tasks. Dispatch commits its files itself (the commit message starts with "Dispatch:"), except while a work run runs without a report, and Approve does not count them as changes. A project of an older version has the folder <project>-reports next to it: Apply moves its files into .dispatch and overwrites nothing. The step shows the number of files first.
Allow rules .claude/settings.local.json Triage can run the worker script and check workers without a permission prompt, except the approve verb of the script: a deny rule keeps it for the Approve button. Each session can read and write the task files in .dispatch without a prompt; Apply removes the rules of an older version that name <project>-reports, and triage can read the job folders of the workers (%USERPROFILE%\.claude\jobs, where a worker keeps the screenshots of its visual test).
Worktree isolation off .claude/settings.json Each worker works in the project folder and not in a separate copy. You see its changes at once.
Section in CLAUDE.md CLAUDE.md Adds the section "Background workers" with the rules for triage and for the workers: a task is two runs of one worker, the plan run edits nothing, your yes starts the work run, and the worker ends with one local commit and never pushes. A section with an older text is replaced.
Working rules CLAUDE.md Adds the section "Working rules": plain words, no duration estimates, only the user's words are approval, reproduce a bug before the fix, scripts write the proof, and more. Each rule has a checkbox. Apply adds the checked rules. With no checked rule, Apply adds no section.
Worker script .dispatch/worker.ps1 The script that starts, resumes and stops a worker. Triage runs it to start a plan run and to send your follow-ups. Dispatch runs it when you click Approve, Reject, Stop or an answer in the Tasks section. It refuses to start the work run when the project has uncommitted changes, when the worker still runs, or when the task was stopped.
Triage role .claude/triage.md Tells the session in the Triage terminal that it is triage: it plans and checks, and it does no implementation. The project settings change this text.

Project settings

The settings are in the Setup pipeline window. The first two are on for a new project, the third is off.

  • Short reports. Triage tells you the result and your decisions in a few lines. It gives details when you ask.
  • Fixed title. A new triage chat has the name "Triage" in the chat list.
  • Approve plans automatically. Dispatch starts the work run as soon as a plan is ready, the project has no uncommitted changes and no other work run runs. A plan whose Decisions section has a decision with the mark HOLD: waits for your click. The line in the triage chat then says "approved automatically". The setting applies at once.

After a change of Short reports, click Apply. The next start of the workspace (Project with that folder, or the start of the app) then opens a new triage chat, because a chat keeps the role with which it started.

The workspace

  • Triage (left). Type your tasks here. For each task, triage writes a brief, starts the plan run of a worker and tells you when the plan is ready. You approve the plan in the Tasks section of the Chats panel, the worker does the work, and triage reports to you. A message that you send from the Chat view is a planned message first: Dispatch keeps it as a file in .dispatch/backlog/ of the project and sends it to triage when triage is free, one at a time, in your order. A message that starts with / (a command of Claude Code) goes at once. The Overview and the Tasks section below tell more. Dispatch writes one line into this chat when a worker is done, blocked or failed, and when you approved, rejected, stopped or answered in the Tasks section. You can click Approve also while another work run edits the project or the project has uncommitted changes: the card then says "Approved · waits for the project", and Dispatch starts the work run when the project is free. Cancel approval takes it back.
  • Chat and Terminal above Triage select its view. Chat shows the messages as formatted text, with a box for your message. Enter sends the message. Ctrl+V adds an image from the clipboard. A question of triage shows its options as buttons: click one, or press Ctrl+Enter for the first. A permission prompt of triage ("Allow this read …?", "Do you want to proceed?") shows the same way, marked Permission. Other… opens the terminal for an answer in your words. Cancel at the right end leaves a question without an answer, like Esc in Claude Code; triage then waits for your message. A permission prompt has no Cancel: use its No. Terminal shows Claude Code itself. Use it for a menu or a slash command.
  • Commands in the chat. A code block has a copy button at its top right. A one-line command also has ▶: it runs the command in a Commands terminal of the project, in the project folder, below the triage chat. The terminal stays for the next command; while a program still runs in it, the next command gets a second one. A command with a part in <…> goes into the terminal without Enter: fill in that part, then press Enter. The × of its bar closes a Commands terminal.
  • Workers (right). This is the agent view of Claude Code. It lists the workers of the project. Select a worker here to look at its work or to answer a permission prompt.
  • Environment in the side panel of a terminal shows the shell, the folder, the branch, the changes and the Claude Code session that runs there. The row Remote Control has a switch: a click on off types /remote-control into that session, on this PC or on its host, and the row says "turning on …" until Claude Code confirms; then it shows the real state again. A click on on types /remote-control too and chooses Disconnect this session in the menu that Claude Code shows; the row says "turning off …" meanwhile. When the menu does not show as expected, Dispatch closes it with Esc and changes nothing. The switch is grey while the session works or waits for an answer.
  • Model and effort. The two lists above Triage apply at the next start of triage. Above Workers there are two pairs: plan for the plan run and work for the work run. They apply to the next run that triage starts.
  • Agents. A worker can start agents for parts of its task in its work run. The fifth list above Workers sets the maximum number of agents that one worker runs at the same time. An agent is a helper that a worker starts; the worker itself does not count as an agent. The number next to the list is the sum of the agents that the workers of the project started; it shows only when a worker started an agent. A plan run starts no agent.
  • The yellow button in the top bar shows when a worker waits for you. Click it to open that worker.
  • Project with that folder at a later time continues your last triage chat of the project. A later Setup pipeline changes the settings and does the steps that are not done.
  • A new triage chat at a limit. The third list above Triage, new chat at …, sets how much context the triage chat may have (100k to 400k tokens, 200k at the start; no new chat turns it off). It applies per project. At the limit Dispatch waits for a quiet moment: triage does not work and asks nothing, the Chat view shows with an empty message box, no line of Dispatch waits, night mode is off, and for 2 minutes there was no turn of triage and no key or click in Dispatch. Then Dispatch closes the chat with /exit and starts a new triage chat in the same pane, with the model and effort above Triage. In the Terminal view the new chat does not start, because Dispatch cannot see what you type there.
  • The hand-off. The first message of the new chat comes from Dispatch: the open tasks and their state, how many are finished, and where the briefs, plans, reports and state files are. It holds nothing of the old chat. The lines of Dispatch that came during the switch go to the new chat after it. From then on Focus, the Map, the task cards and Project use the new chat. The old chat stays in the chat list as "earlier triage"; nothing is deleted.
  • If Claude Code does not end within 30 seconds after /exit, the old chat stays the triage chat, and Dispatch tries again after the next turn of triage. If Dispatch closes during the switch, the next start of triage starts the new chat and gives it the hand-off.
  • A project that has a workspace opens it by itself: at the start of the app, triage continues its chat and the agent view starts; Project with that folder shows the workspace and starts what does not run.

Focus mode

  • Focus at the left of the bar shows one column for each project, side by side: its triage chat with its tasks at the left. Tabs goes back to the terminal tabs and the chat list. Overview shows less: for each project only the tasks in work and a message box.
  • The Triage card at the top of the left panel shows how full the triage chat is: the tokens in use, the size of the window and the share, with a thin bar (it updates within about 10 seconds after a turn). At the limit of the list above Triage it says "new chat when quiet", and "starting a new chat…" during the switch. Its tooltip says what the new chat waits for.
  • The first time, focus mode takes the projects whose workspace is open. The projects group with its pills and + stands in the bar in Tabs, Focus and Map; the Overview hides it. + adds a project folder and starts its workspace; in Tabs it also shows the workspace of the new project. The × of a column removes the project from focus mode; its workspace stays in Tabs.
  • Drag the right edge of a column to give that project or the next one more room, and the edge between the left panel and the chat to widen the panel. Each project remembers its sizes; a double-click on an edge goes back to the usual size.
  • Each project has a pill in the bar: green while a worker works, orange while something waits for you. The pills show the projects of focus mode, or the projects with an open workspace when focus mode has none. A click on a pill goes to the project: in Focus to its column, in the Map to its graph, and in Tabs to its workspace tab (a project without a workspace gets one).
  • Workers in the head of a column opens the agent view of that project below its chat, and a second click closes it. It is closed at the start. A click on a worker row opens it too. The × at the right of the bar of the agent view closes it as well. The workers go on working while it is closed.
  • With two or more projects each project has a thin grey frame, and a blue frame marks the project you work in: the one you clicked or typed in last. Setup pipeline and Rules act on that project. Dispatch remembers focus mode and its projects at the next start.

The Map

  • Map at the left of the bar shows each project of focus mode as a graph: you, triage, one row per task with its plan run and its work run, and the agents of the work run. Green works, orange waits for you, a dashed box starts when you approve. The wires show what passes: tasks to triage, briefs to the plan runs, the approved plan to the work run.
  • A click on something orange shows its card at the right: the plan with Decide, Approve and Reject, or the question of a worker. A click on a run or on the agents opens the worker view.
  • The worker view shows the worker, the agents it started, the last three tool calls and the last message of each, the tokens they wrote and their context, the tool calls by tool, the files they changed, a timeline of all tool calls, and under the run box what the task is about and what it did or does. Dispatch reads the session files twice a second; Claude Code writes a line when a tool call starts and ends, so a message shows when it is complete. Pause stops the updates while you read. Map goes back.
  • The Map shows every task that waits or runs, and the 5 newest finished ones; the others fold into "N more tasks", a click shows them. With many rows, You and Triage stand at the top. In focus mode, Map in the head of a column opens the Map at that project.

Overview

  • Overview at the left of the bar shows one card for each project with an open workspace. Drag a card by the grip ⠿ at the left of its name, or anywhere on its head but the name, to any place; when you let go, the card snaps to a 50 px grid. The dots on the canvas are that grid: the top left corner of a card lands on a dot. Dispatch keeps the places on this computer, so a restart shows them again. The card of a new project takes the first free place. A card that you drop on another lies on top of it; the card you moved last is always on top.
  • A card has three parts. In work lists the tasks in work: a worker that runs, a plan that waits for Approve, a question or a permission of a worker, a worker at a prompt, a plan that you approved until its work run starts, and the message that triage reads now (a temporary card with a dashed edge); without one it says "Nothing in work". Done shows the 5 newest tasks that ended (done, failed or stopped), newest first; without one it says "Nothing done yet". Planned shows your messages that wait for triage, in the order in which triage gets them; without one it shows an empty card with "Nothing planned yet". The tasks have the same buttons as in the Tasks section: Approve, Decisions, Reject, the answers, Continue, Stop. Each task shows the same two lines as in the Tasks section.
  • Planned messages. Each message that you send from the box is a planned card first, also when triage is free; you can type many in a row. Drag a card by its grip at the left, or click ▲ or ▼, to change the order; × removes the message. Dispatch keeps each one as a Markdown file in .dispatch/backlog/ of the project, so it stays after a restart. You can edit or delete a file in an editor; Dispatch follows within a few seconds. When triage is idle and asks nothing, Dispatch sends the first message, word for word. A command that triage runs in the background after its answer does not hold the message. Until then the message waits while triage works, also during a long command of its turn, and the line above the message box says how many messages wait. Its card then stands under In work and says "Sent to triage"; when triage starts the plan run, the task card takes its place and the file goes. A message that gives no task goes after the answer of triage. Focus and the Tasks section show the same cards under Planned. Dispatch commits each change of these files at once, with only these files (the commit message starts with "Backlog:"), so a clone has them and Approve still finds a clean project; an edit in an editor is committed within a few seconds.
  • The box at the bottom of a card is the message box of the triage chat of that project, with the same keys: Enter sends, Shift+Enter makes a new line, Ctrl+V adds an image. A text that you began in Focus stands in it too.
  • No message of the chat shows, also not your own. The line above the box says when triage works or waits. While triage asks a question, the question shows above the box with its buttons; Other… opens the project with its terminal.
  • Record of a question from the screen. Claude Code writes a question into the chat only after your answer, so Dispatch reads the open question from the terminal. Each time it does, it saves what it read in a file: the folder menu-reads in the data folder of Dispatch (on Windows %APPDATA%\com.dani.dispatch\menu-reads), named menu-<date>-<time>-<pane>.json. The file holds the text of the terminal screen at each read, which lines the terminal wrapped, the question and the options that Dispatch made of it, and the times. Dispatch keeps the newest 50 files. When a question shows with a wrong text or wrong buttons, give the newest file to triage with your report. The file holds only what the terminal showed.
  • A click on the name of a project opens it in Focus, or in its tab when focus mode does not have it. A click on a run opens the agent view of the project the same way. Dispatch remembers the Overview at the next start.

Night mode

  • The Nightmode switch in the bar (left of the pane buttons) is green while night mode is on. Turn it on when you go away: the work goes on, and each decision that would wait for you takes its recommended option.
  • The switch is the one state of night mode. The program that does the work keeps it: Dispatch in the mode This PC does the work, each host in the mode Use hosts. In the mode This PC and hosts, Dispatch keeps the switch of this PC and each host keeps its own; the one switch in the bar shows them together. So a restart brings it back as you left it, and every window of a host shows the same switch.
  • With several hosts each host has its own switch. The one switch in the bar is on when every host is on and off when every host is off. When the hosts differ, it shows a third look: the knob in the middle and half the green; its tooltip names the hosts that are on and off. A click on the third look turns night mode on for every host; a click on on turns it off for every host. A host that is not reachable keeps its own switch and is left out of the look until it is back.
  • While the switch is on, the computer that does the work does not go to sleep by itself: this PC in the mode This PC does the work, and each host whose switch is on in the mode Use hosts. In the mode This PC and hosts, this PC stays awake while its own switch is on, and each host while its switch is on. The display may turn off. When the switch goes off, or the program ends (also at a crash), the computer sleeps as before. A computer that only shows a window may sleep. Keep a window open on a computer that stays awake, because the automatic actions of night mode run in a window; the window on the host's PC takes over within about 30 s when the other window sleeps. On a Mac, Dispatch runs the system tool caffeinate for this.
  • On and off send /nightmode start and /nightmode end and a Dispatch line to the triage chat of each project with a workspace. Triage keeps the list of the defaults and writes the morning file (your nightmode skill).
  • The triage chat follows the switch. At each start and each new triage chat, Dispatch compares the switch with the chat's night file (.claude/state/night/night-mode.json) and sends the command again when the chat is behind. The chat never changes the switch.
  • While it is on, Dispatch approves a plan whose decisions all have a default (it writes them into the plan), and answers a question of a worker with its recommended option. Triage hears each default. A plan with a HOLD decision and a report that needs a permission wait for you; triage puts them under Reminders.
  • In focus mode a project whose triage wrote a morning file (.claude/state/night/morning-<date>.md) gets a Morning button at the top of its column. It opens the newest one: the defaults night mode took with their options, what was built, and what waits for you.
  • A question of triage about the night defaults (its text names the night and the defaults) has View defaults in the Chat view. It opens the same morning list in the viewer, and the question stays open: close the viewer, then answer or cancel. Without a morning list the button says "No morning list found".

The Chats panel

  • Triage at the top shows the triage chat of the project. Click it to open it. A triage chat that Dispatch replaced with a new one stands under Chats with the mark "earlier triage".
  • Older chats at the end of the chat list holds the chats that started before the Dispatch setup of the project (when Apply first made its folder .dispatch, or the older reports folder whose files it moved there), also when Claude Code still has them open. A project without the setup has no Older chats. Click it to show or hide them. A search shows them.
  • Tasks shows each task of the project with its worker, its plan and its report. A worker row says Plan run (it reads the code and writes the plan) or Work run (it executes the approved plan; Approve starts it as a copy of the plan run), and shows the state, how long the worker took ("42 s", "4 min", "1 h 12 min"; it counts on while the worker runs) and, when the worker started agents, their number ("3 agents"; "3 agents, 2 active" while some of them work). A row without a number means that the worker does the work itself. The start and the end stand in the tooltip of the row. Dispatch reads the end from the files of Claude Code; a row whose end it cannot read shows the start time instead. The Map shows the same durations. In the agent view of Claude Code (Workers, at the right) the two runs are named <task> [plan] and <task> [work]; a project gets these names after Setup pipeline → Apply. Click the worker to open it. Click the plan or the report to read it. The report row shows the state from the first line of the report. Under the state each task shows two short lines: what it is about (the title of its brief, else your words in the brief, else the title of the plan), and what was done or is in work (the first Summary line of the plan, the first line of the report, or the open question). A long line ends in “…”; its tooltip has both lines in full. Dispatch writes nothing itself: the text is cut from the brief, the plan and the report. A task that you approved while the project was not free shows under its state, with an eye before it, which work run it waits for or how many changed files wait for a commit; its tooltip and the open card have the full reason. A message that you send to triage in the Chat view is a planned card under Planned first (see the Overview). When Dispatch sends it to triage, it shows as a temporary card with a dashed edge: your message, the time, and "Sent to triage", then "Triage reads" while triage works on it. It stands where the new task will stand, after the tasks that wait for you. When triage starts the plan run, the real task card takes its place; a message that gives two tasks gives two task cards. When triage answers without a task, the card goes a few seconds after the answer. A card goes at the latest after 10 minutes, for example when you watch triage in the Terminal view, where Dispatch does not see the end of its turn. The card stays when you close and open Dispatch; its 10 minutes count from your message. The card is not a task: it has no buttons and starts no worker.
  • Plan ready. A task whose plan run is done shows the Summary section of the plan (or its Goal) and its buttons. Approve all takes the recommended option of every decision of the plan (the HOLD ones too), writes them into the plan under "User decisions", and starts the work run of the same worker; a plan without decisions shows Approve. Decisions opens a window with every decision and its options, the ones that wait for you first. The window starts with your words from the brief and the Goal of the plan, so you can weigh each option against them; a long text scrolls inside its box. Under the box stands the TL;DR of the plan: a few lines in plain words that say what changes for you and why, when the plan has one. In the window,click an option, or type your own answer under Other, then Approve with these decisions, or Send back to the planner to have the plan revised with them. It is grey while the project has uncommitted changes or while another work run of the project runs, and the reason shows below it. Reject asks for a reason and sends the planner back with it. A task that waits for you is first in the list.
  • Questions. A worker that needs your decision writes the question into its report with its options, the recommended one first. The task shows the options as buttons. Your click goes to the worker word for word, with the number of the question in front. With several questions each click is a choice: the chosen option is marked, the title counts the questions with a choice, and another click changes it. When every question has a choice, the answers go to the worker together in one reply. A new question also opens a window by itself, like the Decisions window of a plan; Answer in a window in the card opens it again. The window shows every question of the report with its options, the recommended one selected; click another option, then Send the answers sends all answers in one reply. The window does not open by itself in night mode, at the start of Dispatch, or while another window is open. A worker that stopped at a refused step says so in its report; the task shows Continue. Change the rule first, then click it.
  • Stop. A task whose plan run or work run works, or waits at a prompt, shows Stop under its rows. The first click asks; Stop now ends the worker through the worker script, and Keep running lets it go on. The task then says "stopped", and Dispatch writes one line into the triage chat. A stopped task cannot be resumed: the rest of the work needs a new task, which starts clean.
  • Chats shows your Claude Code chats. Click a chat to continue it in a new tab.
  • This project and All projects select the chats that the list shows. The search field finds a chat by its title or by its folder.
  • Drag the right edge of the panel to make it wider or narrower; the terminals keep at least 360 pixels. Dispatch remembers the width, and it is also the usual width of the left panel of each project in focus mode (a panel that you dragged there keeps its own width). A double-click on the edge goes back to the usual width.

Where the work runs

  • Options has three modes. This PC does the work: Dispatch runs the terminals, Claude Code and the workers on this computer, and nothing listens on the network. Use hosts: one or more computers run the program dispatch-host, and this window shows and controls them; nothing runs on this computer. This PC and hosts: Dispatch runs the work of this computer itself and shows and controls the hosts of the list too; no host program runs on this computer. The computers find each other over Tailscale.
  • A change of the mode or of the host list takes effect at the next start of Dispatch.

To work from a second computer, do these steps one time.

  1. On the computer that does the work, open Options and click Start the host in Run the host on this PC. The host listens on the Tailscale address of this computer and on 127.0.0.1, never on all addresses. The Key box shows its key. Dispatch adds the row 127.0.0.1 with the name "This PC" to the host list, switches this window to Use hosts and starts again. On Windows, Start the host at each Windows sign-in starts the host after each sign-in.
  2. On the other computer, open Options, select Use hosts and click Add host. A new row shows: Name, Address, Port, Key and Remove.
  3. Fill in the row. Name: your name for the computer. Address: its Tailscale name (name.tailnet.ts.net) or its 100.x address. Port: empty is 7470. Key: copy it from the Key box of the other computer, or from the file host-key.txt in the data folder of the host.
  4. Close Dispatch and start it again. The window connects to every host of the list. The title says "Dispatch · host <name>" with one host and "Dispatch · hosts <name>, <name>" with more.
  5. Click Project and select a folder of a host. Its workspace opens on that host, as in Set up a project.
  • Several hosts. One window shows the projects of every host. With more than one host, each project name gets " · <host name>" after it: in the pills, the Focus columns, the Map, the Overview cards, the chat groups of All projects and the tab labels. So two projects with the same folder name on two computers stay apart. With one host the names do not change.
  • This PC and hosts. This computer counts as one more computer named "This PC", first in the list. The title says "Dispatch · This PC + host <name>" (or "+ hosts <name>, <name>"), each project name gets " · This PC" or " · <host name>" after it, the bar at the bottom names "This PC" or the host of the focused terminal, and the folder chooser lists "This PC" first. The first tab at a start without saved tabs runs on this PC, and a tab or a project saved in the mode This PC does the work stays on this PC. The bar below the top bar has rows only for hosts that are gone; the terminals of this PC keep working. Nothing on this computer listens on the network. Start the host in Run the host on this PC switches the window to Use hosts, because the host then does the work of this PC.
  • Where a new terminal runs. The first tab at a start without saved tabs runs on the first host of the list. A split runs on the host of the focused terminal. A chat or a worker opens on its own host.
  • The folder chooser. In the modes Use hosts and This PC and hosts, Project and + open a folder chooser inside the window. It lists the folders of a host. Project starts at the folder of the focused terminal; +, or a folder that the host cannot list, starts at the home folder of the host. Click a folder to go into it, or type a path and press Enter, then click Choose. With several hosts a list box at its top selects the host; the host of the focused terminal comes first. In the mode This PC does the work the usual folder dialog of the system opens.
  • A host that is gone. A bar below the top bar shows one row for each host that is not reachable: "Host <name> (<address>:<port>) is not reachable. Dispatch tries again…". Dispatch tries again after 1 second, then after 2, 4, 8 and 10 seconds. The projects and terminals of the other hosts keep working. Typing into a terminal of the gone host goes nowhere, and nothing on that computer stops. When the host is back, a terminal that still runs there continues; a terminal that ended gets a new shell.
  • A host that refused the window, for example with "the key is wrong", gets a row with its reason and Try again. Dispatch does not try again by itself. Correct the key in Options and start Dispatch again; Try again connects once more with the same key.
  • What travels between the computers. Only the window and its hosts talk, and only on the tailnet; Tailscale encrypts the traffic. At the start of each connection the window sends the key, the versions and the id of the window. Then your keystrokes and the terminal output, the chats, the task files, the files that the window shows, and a pasted image as bytes travel. The window keeps its tabs, its saved terminal screens, its theme and its other choices on its own computer. The host keeps the terminals of a closed window, and the Nightmode switch and the triage chats of its projects.
  • Run the host on this PC in Options. Start the host: see step 1. Stop the host ends the host and its terminals and removes the row 127.0.0.1 from the list and starts Dispatch again; with an empty list this window goes back to This PC does the work. New key starts the host again with a new key; every other window needs the new key in its row.

Other buttons

  • The four icons split the terminal to the right, split it down, close it, and show or hide the side panels.
  • Rules shows all the rules that Claude Code gets in the project. Copy all puts them into the clipboard as text. Analyse rules asks Claude Code which rules are obsolete or problematic; the three lists left of it set the time limit of the check (3 to 30 minutes, Dispatch stops the check after it), the model and the effort. Dispatch keeps the choice on this computer, and the check of the Setup pipeline window uses the same values. While a check runs, the line above the findings shows the time that passed and the limit.
  • Each rule of a Markdown file has two buttons. Off takes the rule out of the file; the list keeps it with a line through it, and On puts it back at the end of its group. Remove deletes the rule after a second click. The rules that are off are kept on this computer only. A rule of the triage role comes back with the next Apply of Setup pipeline. The settings in JSON files have no buttons.
  • Update to … shows when a new version is available. A click saves your tabs, downloads the installer and installs in one step: Dispatch closes, a progress bar runs, and the new version opens with your tabs. On a Mac the click downloads the disk image and opens it, and Dispatch closes: drag Dispatch to Applications and start it again; the app is not signed, so run xattr -cr /Applications/Dispatch.app in Terminal once before that start. The check reads the public releases on GitHub and needs no login and no extra tool. The line below the title of this window shows the version and the result of the check. Dispatch checks once an hour; Check for update next to that line checks now, and after it found a new version it installs it.
  • Options (the gear next to ?) opens the Options window. It holds where the work runs (see Where the work runs above), the alerts, the colour theme of the window and the terminals (Slate, or Graphite with a blue, indigo, teal or amber accent) and the size of the text in the window and in the terminals (90 to 150 percent). A change applies at once, and Dispatch keeps the choices on this computer.
  • Alerts. When a task starts to wait for you, Dispatch alerts you one time: a plan is ready, a report has a question or needs a permission, or a worker waits at a prompt. Each alert has its own switch in Options: a system notification that names the task and what it waits for, a short, quiet chime, and the Dispatch button in the taskbar that blinks until you open the window. The tasks that already wait when Dispatch starts give no alert. The chime plays only after your first key or click in Dispatch since its start, because the window may play sound only then. While night mode is on, only a plan with a HOLD decision, a permission and a prompt alert, because night mode takes the other decisions itself. A test build that runs with npm run tauri dev shows the notification as from PowerShell.
  • The bar at the bottom shows on its right side "Claude account:" with the email of the Claude account that Claude Code is signed in with on the computer that does the work, then the weekly usage of that account for all models and for Fable, the version of Claude Code and the version of Dispatch. The computer that does the work is this PC, or the computer of the focused terminal in the modes Use hosts and This PC and hosts. With several hosts the name of that host stands in front of the account, and a click in a terminal of another host shows the values of that host. When the versions of this window and a host differ, the version part shows both versions in the wait colour; with several hosts it names the host. Dispatch reads the account and the versions at the start and then once a minute, so a new login or an update of Claude Code shows within a minute. The email stays on this computer. Without a login the bar says "Not signed in to Claude Code"; without Claude Code it says "Claude Code not found".
  • The weekly usage in the bar, for example "Week: all models 41 % · Fable 7 %", is the percent of the weekly limits of your subscription that is used, as /usage of Claude Code shows it. After it the bar shows when the week starts again, for example "Resets Jan 1, 9:00am": one time when both limits reset together, and each with its name when they differ; the tooltip adds the time zone. Dispatch reads it at the start and then every 5 minutes; each read starts Claude Code for a moment without a window, and Claude Code asks Anthropic for the numbers. The tooltip of each value says when the week starts again and when Dispatch read it. The numbers stay on this computer. When they cannot be read the bar says "Usage not known" and keeps the last values; an account without a weekly limit shows "No weekly limit", and "Fable: no weekly limit" when the usage screen has no line for Fable. Without a login or without Claude Code the two values are empty. In a narrow window the email is cut first, then the versions.
